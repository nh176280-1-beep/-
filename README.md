# 한눈에 시세

금천미트는 검색어 제한 없이 공개 API의 모든 카테고리를 조회합니다. 상품번호 정렬과 중복 제거를 적용하며 API의 검색 1만 건 상한을 고려해 분할 조회합니다. 일품한우는 메인의 전체 카테고리 링크에서 실제 상품 목록을 마지막 페이지까지 조회합니다. 로그인 전용 가격은 제외하고, 공개 상품은 중량 단가와 상품 총액을 구분합니다. 금천미트 재고는 수집 중에도 변하므로 시작·종료 건수를 모두 기록합니다. 원본 API는 한 시점에 고정된 전체 재고 스냅샷을 제공하지 않습니다.

대구축협 육가공공장 직원용 모바일 가격 조회 웹앱입니다. 금천미트(EKCM)와 일품한우의 공개 가격을 한 화면에서 조회하기 위한 앱으로, 직원별 로그인을 사용합니다.

## 서버 없이 화면 체험하기

클라우드 환경 설정 채팅은 실행 중인 웹앱의 실시간 미리보기 창을 지원하지 않습니다. 대신 [독립 실행 체험 파일](preview/index.html)을 브라우저에서 열면 로그인이나 서버 없이 검색·사이트 필터·관심 품목 저장을 체험할 수 있습니다. 파일 내부에 화면과 스타일, 예시 데이터가 모두 들어 있습니다. 채팅에서 HTML이 바로 실행되지 않으면 파일을 내려받아 Chrome·Safari 등의 브라우저로 여세요.

**체험 파일의 가격 8개는 가상의 예시이며 실제 판매 가격이나 수집 결과가 아닙니다.** 실제 앱의 계정·수집 데이터는 파일에 포함하지 않습니다. 실제 직원 서비스의 인증과 배포는 별도로 필요합니다.

- [체험용 모바일 화면 이미지](docs/preview-mobile.png)
- [체험용 데스크톱 화면 이미지](docs/preview-desktop.png)

화면 코드 변경 후에는 `npm run preview:build`로 파일을 재생성합니다. 생성기는 `public/` 화면 코드만 사용하며 `data/`나 계정을 읽지 않습니다. 오프라인 브라우저 테스트로 검색·필터·관심 품목 저장 및 추가 네트워크 요청이 없음을 검증했습니다. 이 환경의 관리형 Chromium은 `file://` 열기를 제한하므로 테스트에서는 문서만 파일에서 공급하고 모든 네트워크를 끈 상태로 실행했습니다. 일반 브라우저의 파일 열기 자체는 이 환경에서 검증할 수 없었습니다.

## 현재 확인 상태

- 구현: 직원 로그인, 관리자 계정 추가·중지·비밀번호 재설정, 품목/등급 검색, 사이트 필터, 관심 품목, 원본 링크, 수집 시각과 갱신 실패 표시.
- 구현: 30분 주기 서버 수집, JSON-LD KRW 상품 가격 및 단순 HTML 가격표 해석, 마지막 성공 가격 보존.
- 일품한우: 거세·암소 전체 카테고리의 실제 상품 목록을 200개씩 조회합니다. 원본 표시 총건수와 실제 목록이 다르면 `partial`로 표시하고 차이를 공개합니다. 이를 전체 완료로 판단하지 않습니다.
- 금천미트: 공개 API 전체 상품을 250개씩 조회합니다. API 전체 건수와 조회 건수를 대조하고, 비공개·유효 가격 또는 단위 확인 불가 상품 수를 별도로 표시합니다. 수집 중 재고 변동이 있으므로 종료 시점의 전체 건수를 다시 확인합니다.
- **외부 서버에 아직 배포하지 않았습니다.** 아래 배포 설정은 준비되어 있으며, 클라우드 계정 및 배포가 필요합니다.
- 자동화 테스트의 가격은 격리된 테스트 데이터이며 운영 데이터에 포함하지 않습니다.
- 코드 검증과 실가격 검증은 별개입니다. Docker 컨테이너에서 운영 세션 쿠키·로그인·접근 제한 및 영구 볼륨의 직원 계정 재시작 보존을 확인했습니다. Render 배포와 외부 HTTPS 연결은 아직 검증하지 않았습니다.

화면: [모바일](docs/mobile-preview.png) · [데스크톱](docs/desktop-preview.png). 화면 이미지는 당시 실제 수집한 일품한우 상품을 사용하며, 임시 검증용 직원 계정으로 촬영했습니다. 해당 임시 계정은 운영 데이터에 남아 있지 않습니다.

## 로컬 실행

### 접속이나 로그인이 안 될 때

- 위의 화면 링크는 PNG 이미지이며 실행 앱 주소가 아닙니다. 외부 휴대폰 접속에는 실제 서버 배포 후 발급되는 HTTPS 주소가 필요합니다.
- 클라우드 작업 환경이 다시 시작되면 앱 프로세스는 종료될 수 있습니다. `npm start`로 다시 실행해야 합니다.
- `아직 관리자 계정이 등록되지 않아 로그인할 수 없습니다`가 보이면 아래 초기 관리자 환경변수를 설정하고 서버를 재시작해야 합니다. 임의의 기본 비밀번호는 없습니다.
- 테스트용 아이디는 격리된 테스트 서버에만 존재하며 실제 앱에는 없습니다.
- `/health`의 정상 응답은 서버 실행 여부만 뜻합니다. 계정 등록·원본 가격 수집·외부 배포 완료를 뜻하지 않습니다.
- 수집 상태에서 전체 확인·수집 중·일부 확인·실패를 구분합니다. 일부 목록만 받았거나 원본 총건수가 맞지 않으면 전체 완료로 표시하지 않습니다.

Node.js 24 이상을 사용합니다.

```sh
cd /workspace/-
npm ci --cache /workspace/.npm-cache
cp .env.example .env
```

`.env`에서 `ADMIN_USERNAME`과 `ADMIN_PASSWORD` 주석을 풀고 관리자 아이디와 12자 이상의 고유한 비밀번호를 설정한 뒤 실행합니다. 비밀번호를 저장소에 커밋하거나 채팅으로 전달하지 마세요. `.env`는 Git에서 제외됩니다.

```sh
npm start
```

포트 기본값은 3000입니다. 관리자 환경변수는 **계정이 하나도 없는 최초 실행**에만 사용되며, 환경변수 값을 바꾸어도 기존 계정 비밀번호가 바뀌지 않습니다. 초기 설정 후에는 관리자 비밀번호 환경변수를 제거해도 저장된 계정으로 로그인할 수 있습니다. 관리자 계정이 없으면 로그인은 허용되지 않습니다. 개발용 기본 계정이나 기본 비밀번호는 없습니다.

이 환경은 이미 격리되어 있으므로 기존 체크아웃을 사용합니다. 사용자의 명시적인 요청 없이는 별도 Git worktree를 만들지 않습니다.

## 새 클라우드 서버 배포: Render

[`render.yaml`](render.yaml)은 Docker 웹 서비스 1개와 1GB 영구 디스크를 구성합니다. **유료 Starter 서비스와 디스크**를 사용합니다. 생성 화면에서 표시되는 요금을 확인해야 하며, 이 파일 자체로 서버가 만들어지거나 비용이 발생하지 않습니다.

1. 이 코드와 `package-lock.json`, `render.yaml`이 포함된 GitHub 브랜치를 선택합니다.
2. Render 계정에서 **New → Blueprint**를 선택하고 이 GitHub 저장소와 코드를 포함한 브랜치를 연결합니다.
3. 서비스와 디스크 요금을 검토한 뒤 생성합니다. 플랫폼에서 HTTPS 주소가 발급됩니다.
4. Render의 Environment 화면에서 자동 생성된 `ADMIN_PASSWORD`를 안전하게 확인하고, `admin` 아이디로 첫 로그인합니다. 이 비밀번호를 직원에게 공유하지 않습니다.
5. 관리 설정에서 직원별 아이디와 비밀번호를 생성합니다. 직원에게는 배포된 HTTPS 주소와 각자의 계정을 전달합니다.
6. 관리 설정에서 `지금 수집`을 실행합니다. 수집 요청은 즉시 응답하고 백그라운드에서 계속됩니다. 가격 조회 화면에 진행 건수가 표시됩니다. 완료 후 품목·가격·단위를 원본과 대조한 뒤 운영합니다.
7. 커스텀 도메인을 연결할 경우 `PUBLIC_URL=https://사용할도메인`을 설정합니다. 기본 Render 도메인은 `RENDER_EXTERNAL_URL`을 사용합니다.

서버 프로세스는 하나만 실행해야 합니다. JSON 파일 저장 방식이므로 다중 인스턴스·다중 writer 구성은 지원하지 않습니다. 대규모 사용 시 PostgreSQL 등의 공유 데이터 저장소로 전환하세요.

배포 후 확인할 항목:

- 서버 환경에서 `npm run check:sources`를 실행합니다. 이 검사는 이전 저장 가격을 읽지 않고 두 사이트에서 새로 수집하며, 한 곳이라도 실패하거나 품목이 없으면 종료 코드 1을 반환합니다. 두 사이트 모두 성공해야 실가격 연동이 준비된 것입니다.
- `/health` 응답이 `{"status":"ok"}`인지 확인합니다. 이것은 서버 상태 확인이며 원본 가격 수집 성공을 의미하지 않습니다.
- 비로그인 상태에서 `/api/prices`는 HTTP 401이어야 합니다.
- 관리자 로그인, 직원 추가, 직원 로그인, 관리자 메뉴 접근 차단을 확인합니다.
- 두 사이트의 수집 상태와 확인 시각 및 실제 가격·판매 단위를 확인합니다.
- 서비스를 재시작해 계정과 수집 가격이 유지되는지 확인합니다.
- 휴대폰의 이동통신 연결로 HTTPS 주소에 접속해 확인합니다.

## 데이터 수집과 제한

현재 HTML 수집 대상 도메인은 다음 네 개로 제한되어 있습니다. 외부 호스트로의 리디렉션, 임의 URL, HTTP 연결을 허용하지 않습니다.

```text
www.ekcm.co.kr
ekcm.co.kr
www.ilpoomhanwoo.com
ilpoomhanwoo.com
```

금천미트 API 수집에는 추가로 `gw.ekcm.co.kr`이 필요합니다. 다섯 도메인의 허용 설정 후 실제 수집에 성공했습니다. 실행 샌드박스가 EPERM을 반환하는 경우 승인된 네트워크 실행으로 구분해 확인합니다. 검사 출력의 `errorCodes`에서 연결 실패 코드를 확인할 수 있습니다. **Codex 환경 게시는 직원용 인터넷 서비스 배포와 별개입니다.**

`src/prices.js`는 실제 일품한우 공개 상품 카드에 맞춘 수집기와, 통화가 명시된 JSON-LD `Product.offers` 및 품목·가격 열이 명확한 HTML 표 수집기를 포함합니다. 일품한우의 `kg당` 가격과 상품 총액을 구분하며 직접 계산해 대체하지 않습니다. 범위 가격, 여러 가격 열, 이미지 가격표, 로그인 전용 가격, 지원되지 않는 동적 가격표는 추측하지 않습니다. 구조화 데이터에서 단위를 알 수 없으면 `단위 미표기`로 표시합니다. 등급·단위가 다른 상품의 최저가를 추천하지 않습니다.

사이트별 `robots.txt`를 확인하며 robots.txt 404는 규칙 부재로 처리합니다. API 호스트의 규칙도 확인합니다. 페이지당 12초와 2MB 제한을 적용하고, 페이지 사이에 200ms 간격을 둡니다. HTTP 429·5xx·일시 연결 실패는 최대 3회 시도합니다. 403이나 로그인 요구는 우회하지 않습니다. 첫 수집에는 수 분이 걸릴 수 있으며, 전체 성공 전에는 이전 정상 가격을 유지합니다. 일품한우 원본 표시 건수와 실제 반환 목록의 차이는 `partial` 상태로 명시합니다.

사이트 변경 또는 실패 시 마지막 정상 가격을 유지하고 갱신 지연으로 표시합니다. 페이지 주소를 변경하면 해당 사이트의 이전 가격을 제거합니다. 화면의 `조회 새로고침`은 저장된 서버 정보만 다시 읽으며, 원본 재수집은 관리자 `지금 수집` 또는 30분 주기 작업이 수행합니다.

## 계정과 저장

- 비밀번호: 계정별 salt + scrypt 해시. 세션: HttpOnly/SameSite=Strict 쿠키, 운영 시 Secure, 만료 8시간.
- 로그아웃·계정 중지·직원 비밀번호 재설정 시 해당 계정의 기존 세션이 만료됩니다.
- 관리자 `직원 계정 복구`에서 직원 비밀번호를 재설정하고 계정을 다시 활성화할 수 있습니다.
- 상태 변경 API는 같은 출처의 JSON 요청만 허용합니다. 가격 API는 로그인이 필요합니다.
- `DATA_DIR`(기본 `./data`)에 계정·세션 서명 키·수집 상태·가격·페이지 설정이 저장됩니다. 이 디렉터리는 민감 데이터이므로 접근을 제한하고 암호화된 백업을 운영하세요. 라이브 프로세스 하나만 이 디렉터리를 써야 합니다.
- 관심 품목은 사용자 아이디별 브라우저 저장소에 저장됩니다. 기기 간 동기화와 오프라인 가격 저장은 지원하지 않습니다.
- 운영은 반드시 HTTPS로 제공하고 `NODE_ENV=production`을 설정합니다. 프록시 뒤 로그인 시도 제한은 보수적으로 동일 프록시 IP에 합산될 수 있습니다.

## 테스트

```sh
npm test
# Chromium이 설치된 이 개발 환경
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
# 다른 개발 환경에서는 먼저 아래 명령으로 테스트용 브라우저 설치
npx playwright install chromium
npm run test:browser
```

서버 테스트는 인증·권한·CSRF·수집 허용 범위·가격 해석·장애 시 데이터 보존·재시작 지속성을 확인합니다. 브라우저 테스트는 격리된 테스트 서버로 휴대폰 로그인·검색·관심 품목·로그아웃과 관리자 직원 관리를 확인합니다. 실제 원본 사이트 검증 및 외부 배포 검증을 대체하지 않습니다.

환경 프록시가 사용자 지정 CA를 사용하는 경우 다음과 같이 기존 신뢰 인증서 묶음을 **빌드 시에만** 전달할 수 있습니다. TLS 검증은 유지하고 인증서를 이미지에 저장하지 않습니다. 일반 클라우드 빌드에서는 이 옵션이 필요하지 않습니다.

```sh
BUILDX_CONFIG=/tmp/daegu-buildx docker build --secret id=build_ca,src=/etc/ssl/certs/ca-certificates.crt -t daegu-meat-prices .
```
